# Публикация 0.3.0

## Текущий статус
Первичная установка использует release/pack.json и pack.json.sig рядом с лаунчером. Встроенные objects содержат только файлы Arcane Genesis. 127 внешних файлов загружаются по абсолютным официальным HTTPS-адресам. Java, Minecraft и NeoForge устанавливаются отдельно из официальных источников. Старый prepare-runtime.ps1 — архивный инструмент локального импорта; в распространении 0.3.0 он не используется.

Репозиторий: https://github.com/Lycean415/ArcaneGenesis-Releases. Выпуски launcher-0.3.0 и pack-0.3.0-preview.1 опубликованы, оба канала подписаны и проверены.

## Подготовка выпуска
1. Подготовить чистую папку сборки без миров, аккаунтов, скинов игроков и тестовых модов.
2. Для сторонних файлов сохранить точные официальные URL, SHA256 и размеры. Новые версии проверять заново. prepare-distribution.ps1 формирует текущую проверенную поставку из локальных исходников; -Resume продолжает только создание манифеста уже подготовленного этапа.
3. Сохранить release-private.pem вне репозитория. Этот ключ подписывает манифесты RSA-PSS/SHA256. В приложение входит только release-public.pem.
4. build.ps1 создаёт автономное приложение и установщик. Исходники и проверенный манифест должны соответствовать одному выпуску.

## GitHub Releases
Использовать существующий публичный репозиторий ArcaneGenesis-Releases. Не загружать туда старый локальный object store, Minecraft, приватные ключи или decompiled-исходники.

Для модпака создать отдельный тег, например pack-0.3.1. Загрузить наши объекты из release/objects как assets с именами SHA256. В новом pack.json заменить относительные URL наших объектов на полные https://github.com/OWNER/REPO/releases/download/pack-0.3.1/HASH. Внешние адреса Modrinth/CurseForge оставить исходными. Установить новую version. Подписать уже окончательный JSON командой:

    dotnet Arcane.Tools.dll sign pack.json /закрытый/путь/release-private.pem

Опубликовать pack.json и pack.json.sig. Для постоянного адреса можно держать эти два подписанных файла в ветке channels/pack либо в отдельном служебном релизе. Не использовать общий releases/latest для независимых потоков лаунчера и модпака: последний релиз может относиться к другому продукту.

Для лаунчера создать отдельный тег launcher-0.3.1. Сначала загрузить готовый установщик. launcher.json имеет поля schema=1, version, url (полный HTTPS-адрес установщика), sha256, size. Подписать JSON той же командой sign. Опубликовать launcher.json и .sig в отдельном постоянном канале channels/launcher. Обновление лаунчера проверяется независимо от версии сборки.

Указать проверенные постоянные адреса Channel и LauncherChannel в channel.json следующего установщика. RuntimeChannel оставить official:1.21.1-neoforge-21.1.265. Текущие пользователи могут указать адреса в настройках. Публичные ключи должны совпадать с ключом подписи. Вначале проверить обе подписи, скачивание с нового устройства, восстановление испорченного файла и запуск.

Для будущих обновлений самого приложения лучше вынести доверенные адреса каналов в отдельный подписанный каталог; текущая версия не обещает автоматического обнаружения ещё не существующего репозитория.


## Следующий выпуск
Опубликованные файлы версии 0.3.0 не заменять: новый установщик получает новую версию и тег. Перед повторным использованием .github/workflows/release.yml поменять версию приложения, пути исходного ZIP и теги релизов. Не перезапускать публикацию изменённого установщика под прежним номером: подписанный launcher.json привязан к точным байтам EXE.
