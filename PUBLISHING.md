# Публикация следующих версий Arcane Genesis

Текущие каналы: channels/launcher/launcher.json и channels/pack/pack.json в ветке main. Обновляйте каждый JSON вместе с его .sig одним коммитом только после проверки доступности всех файлов релиза. Не используйте общий releases/latest для этих двух независимых потоков.

## Лаунчер

1. Измените Version в Directory.Build.props. Соберите и проверьте чистый архив исходников, не включающий private, bin, obj, tools, игровые файлы, журналы и тестовые миры.
2. Создайте новый сценарий сборки с новой версией и закреплённым SHA256 архива. Архив SDK скачивается из официального источника и проверяется по SHA512.
3. Запустите тесты и сборку установщика на Windows. Опубликуйте новый тег launcher-VERSION с EXE, его SHA256, исходниками и отчётом. Существующие assets не заменяйте.
4. Скачайте опубликованный EXE, сверьте хеш и проверьте его установку. Сформируйте launcher.json: schema=1, version, полный HTTPS url, sha256, size.
5. Подпишите точные байты JSON существующим ключом RSA-PSS/SHA256 локально. Приватный ключ не помещается в репозиторий, исходники, логи или GitHub Actions. Команда инструмента: dotnet Arcane.Tools.dll sign MANIFEST PRIVATE_KEY_PATH.
6. Проверьте подпись публичным ключом и загрузку точного EXE. Загрузите JSON/.sig в релиз, затем атомарно переключите постоянный канал.

## Модпак

1. Подготовьте чистый каталог без миров, персональных настроек и диагностических модов. Для внешних файлов сохраните исходные разрешённые HTTPS-адреса, размеры и SHA256.
2. Наши файлы помещаются в objects с именами SHA256. Пользовательские конфигурации используют policy=seed; управляемые файлы сборки — managed. Изменение набора файлов требует новой версии, даже если исправлены только метаданные.
3. В публичном рецепте URL собственных объектов указывают на новый тег pack-VERSION; внешние URL остаются исходными. Подпишите окончательные байты рецепта.
4. Опубликуйте все собственные объекты, pack.json и pack.json.sig. Сверьте состав, размеры, хеши и подпись; затем переключите channels/pack обоими файлами одним коммитом.
5. Для встроенной первой установки в лаунчере допустим отдельный подписанный рецепт той же версии с относительными objects/URL. Пути, размеры, хеши и policy должны совпадать с публичным рецептом; различаться могут адреса загрузки.

Не изменяйте оригинальные JAR сторонних модов. Не публикуйте игровые бинарники Minecraft, приватные материалы аудита или ключи. Новые версии подписанного содержимого публикуются под новыми номерами. Отозванные версии сохраняйте для истории и исключайте из активного канала.
